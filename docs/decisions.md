# Sentinel Decisions

This file records the implementation decisions approved before development. `docs/architecture.md` provides the operating detail. Changes to these decisions should be deliberate and documented here before expanding implementation scope.

| Decision              | Agreed direction                                                                                                                                                                                       | Practical consequence                                                                                                                                                                                                                                                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product shape         | Build a CLI, not a lightweight service.                                                                                                                                                                | One documented command runs a scan; there is no daemon, API server, or persistent state.                                                                                                                                                                                                                                                                |
| Report format         | Render exactly one configured Markdown, JSON, or plain-text terminal report; default to Markdown.                                                                                                      | All formats consume one validated model and Overall Summary. JSON requires a path; terminal writes only to stdout and forbids a path.                                                                                                                                                                                                                   |
| Supported stacks      | Provide deep Node/npm support plus useful generic repository behavior.                                                                                                                                 | Unknown stacks still receive static repository/security checks. Python, Java, Go, pnpm, and Yarn depth is deferred.                                                                                                                                                                                                                                     |
| Stack detection       | Detect Node/TypeScript from repository evidence; otherwise select generic mode.                                                                                                                        | Detection must change behavior meaningfully rather than only adding a label.                                                                                                                                                                                                                                                                            |
| Repository inspection | Build one bounded, symlink-safe inventory before checks and read selected text files through a shared size limit.                                                                                      | Retain relative paths and file kinds rather than repository contents. An incomplete inventory cannot produce a definitive absence warning. Static code-style and test passes require readable, nonempty evidence; bounded script heuristics reject obvious no-op or unreachable cases but never claim shell parsing, tool execution, or test execution. |
| Execution model       | Validate shared prerequisites and cache service reachability before running the four analysis-level groups concurrently.                                                                               | Dormant projects remain valid targets; missing runtime context becomes `Skipped / Info` availability notes rather than errors.                                                                                                                                                                                                                          |
| Service discovery     | Probe only configured API/UI targets.                                                                                                                                                                  | Do not scan ports or guess local services. Any HTTP response counts as reachable.                                                                                                                                                                                                                                                                       |
| Service lifecycle     | Never start, stop, or restart target services.                                                                                                                                                         | Missing services produce fallback or skipped results, not process execution.                                                                                                                                                                                                                                                                            |
| Runtime safety        | Runtime API checks are read-only.                                                                                                                                                                      | Only configured or safe `GET`, `HEAD`, and `OPTIONS` operations are eligible.                                                                                                                                                                                                                                                                           |
| Execution scheduling  | Run the four fixed analysis-level groups concurrently and checks sequentially within each level.                                                                                                       | Every check owns an explicit timeout and isolated failure row; result order remains deterministic by level and registration order.                                                                                                                                                                                                                      |
| Configuration         | Use one recursively strict Zod schema with optional `sentinel.config.json`, `.env`, and process-environment overrides.                                                                                 | Precedence is process environment, `.env`, JSON, then the target/report defaults. Unknown keys and invalid supplied values are fatal. Target-specific values are never hardcoded.                                                                                                                                                                       |
| Missing configuration | Continue every independently runnable check when optional API/UI sections or credentials are absent.                                                                                                   | Invalid or incomplete supplied sections are fatal; missing runtime sections and optional credentials produce skipped results. Unreadable roots and unwritable reports remain fatal.                                                                                                                                                                     |
| Dependency freshness  | Query root npm projects once with bounded, read-only `npm outdated`; do not execute package scripts.                                                                                                   | Missing npm, timeout, or registry failure produces `Skipped / Info`. Tests inject deterministic output and never contact a registry.                                                                                                                                                                                                                    |
| Dependency audit      | Run bounded npm audit only for a root npm project with exactly one `package-lock.json`.                                                                                                                | A clean pass requires exit code 0 and a validated, internally consistent empty v2 report. Vulnerability reports require exit code 1; every npm/error-envelope failure remains skipped.                                                                                                                                                                  |
| Secret detection      | Detect only complete plausible private-key blocks, high-confidence provider signatures, and secret-like environment-file assignments.                                                                  | Detector definitions and incomplete key fragments do not count. Findings retain relative path, line, and detector category only. Entropy, Git history, and generic source password/token heuristics are out of scope.                                                                                                                                   |
| Environment hygiene   | Review real `.env` variants and templates separately using root ignore rules.                                                                                                                          | Unignored real files warn High; ignored templates warn Low. Secret values are not read by this check.                                                                                                                                                                                                                                                   |
| Security runtime      | Observe only configured unauthenticated targets and evidence-derived debug routes with read-only requests.                                                                                             | Cached reachability gates requests; target credentials are never resolved, redirects are not followed, and paths are never brute-forced. Header/CORS results are consolidated, and weak or unverified policies warn instead of passing.                                                                                                                 |
| OpenAPI               | Require one explicit target-contained OpenAPI 3.0/3.1 JSON/YAML path for configured APIs.                                                                                                              | Never guess or fetch the contract. Validate configured status/content plus supported top-level JSON response shape without building a full schema engine; non-JSON schemas and malformed supported operations remain visible limitations that prevent a document-level pass.                                                                            |
| API analysis mode     | Select live analysis or static OpenAPI fallback exclusively from the cached API reachability result.                                                                                                   | Reachable APIs receive one read-only request per bounded configured endpoint; unavailable APIs receive only static contract alignment findings. Never switch modes after endpoint failures.                                                                                                                                                             |
| Route fallback        | Treat source-derived routes as best-effort candidates.                                                                                                                                                 | Never claim complete API coverage without an authoritative contract.                                                                                                                                                                                                                                                                                    |
| Browser automation    | Use one composite Playwright Chromium check with one browser launch and shared public/authenticated contexts.                                                                                          | Page loads feed navigation, console, image, axe, and horizontal-overflow results. Absence of overflow does not claim responsive adaptation. Indeterminate axe evidence prevents an accessibility pass without marking successful execution incomplete. A launch failure remains an incomplete-scan skip.                                                |
| Form checks           | Run only explicitly configured form flows at the widest configured viewport.                                                                                                                           | Accept at most five flows and 20 steps per flow; never discover and submit arbitrary forms.                                                                                                                                                                                                                                                             |
| AI use case           | Perform semantic API test-gap analysis.                                                                                                                                                                | Compare bounded route/contract evidence with relevant tests; return a supported `gap` or informational `no_supported_gap`, and do not use AI merely to summarize the report.                                                                                                                                                                            |
| AI request model      | Give checks one provider-neutral typed client backed by an explicit OpenAI-or-Claude transport switch. Use each vendor's native schema-constrained output and validate again with the same Zod schema. | One client permits one paid request total and one active request per scan. Checks never receive vendor envelopes; there is no inference, registry, retry, streaming, or provider comparison.                                                                                                                                                            |
| AI fallback           | Treat disabled AI or a missing selected-provider credential as an ordinary skip; fail closed after dispatch for every unavailable or unrecognized response.                                            | Dispatched failures consume the call allowance, produce `Skipped / Info`, and mark the scan incomplete. AI can warn or fail but can never produce a pass.                                                                                                                                                                                               |
| AI evidence           | Select one configured target OpenAPI contract and one related readable test through bounded, redacted repository evidence.                                                                             | Inspect at most 12 candidates, send at most 8 KiB, use only target-relative citations, and skip without a request when safe relevant evidence is insufficient. Route-source fallback and multiple-test synthesis remain deferred.                                                                                                                       |
| Secret handling       | Redact repository and target secrets before storage, logging, reporting, or AI evidence transmission. Use a selected provider credential only as an authentication header.                             | Real provider credentials never enter prompts, request bodies, response evidence, reports, logs, tests, or documentation. Detected target secrets are never transmitted without redaction.                                                                                                                                                              |
| Check results         | Use one runtime-validated result per stable check-and-subject pair.                                                                                                                                    | Status, finding, severity, and recommendation are mandatory even for skipped rows; results aggregate into one normalized Overall Summary.                                                                                                                                                                                                               |
| Execution errors      | Distinguish incomplete execution or coverage from normal prerequisites and indeterminate evidence.                                                                                                     | Isolated execution/coverage failures remain nonfatal but produce diagnostic rows and an incomplete-scan summary. Successfully collected indeterminate evidence remains visible without changing the whole scan status.                                                                                                                                  |
| Exit codes            | Return nonzero only for fatal tool errors.                                                                                                                                                             | Findings, unreachable services, and isolated check errors remain report content rather than CI policy.                                                                                                                                                                                                                                                  |
| Tooling               | Use Commander, Zod, strict ESM TypeScript, Vitest, ESLint flat config, and Prettier.                                                                                                                   | Prefer established, small boundaries over custom infrastructure; `npm run check` is the shared local and CI quality gate.                                                                                                                                                                                                                               |
| Clean-machine setup   | Support `npm install` followed by `npm start` on Node.js 20.19 or later with no required environment configuration.                                                                                    | `prestart` compiles automatically. Root installation also installs the standalone sample package with scripts disabled; browser checks require the separate `npx playwright install chromium` command.                                                                                                                                                  |
| Demo target           | Keep the deliberately flawed Express/TypeScript target as a standalone nested npm project with its own manifest and lockfile.                                                                          | Root-focused scans can inspect its real dependency boundary. The reviewer starts it separately; Sentinel never manages its process.                                                                                                                                                                                                                     |
| Testing               | Use Vitest for Sentinel and Node's built-in test runner for the standalone sample; focus automation on risky logic and degradation paths.                                                              | Browser automation uses deterministic injected session fakes in the normal suite; the real Chromium/axe path is verified against the separately started sample.                                                                                                                                                                                         |
| Scope control         | Prefer KISS and finish required deliverables before stretch work.                                                                                                                                      | Do not introduce plugins, DI containers, schedulers, databases, deep multi-stack adapters, simultaneous multi-format output, or formats beyond the approved three.                                                                                                                                                                                      |

## Fatal Tool Errors

The agreed fatal cases are deliberately narrow:

- The target root cannot be read.
- Configuration syntax cannot be interpreted safely.
- Configuration contains an unknown, invalid, or incomplete supplied value.
- The selected report cannot be rendered or written.

All other unavailable capabilities or isolated check failures should be represented transparently in the report.
