# Sentinel Decisions

This file records the approved implementation decisions that constrain the
current MVP. [`docs/architecture.md`](architecture.md) provides operating
detail, [`docs/configuration.md`](configuration.md) defines the configuration
contract, and [`README.md`](../README.md) is the reviewer runbook. Expanding a
boundary requires an explicit decision rather than an inferred abstraction.

## Product and Execution

| Decision                             | Agreed direction                                                                                                                                                                                                                                   | Practical consequence                                                                                                                                                                                                                                   |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product and report shape             | Build an on-demand CLI that emits exactly one selected Markdown, JSON, or plain-text terminal report.                                                                                                                                              | There is no daemon, API server, database, or persistent state. Every renderer consumes one validated report and Overall Summary; Markdown is the default, JSON requires a path, and terminal output forbids one.                                        |
| Supported stacks                     | Provide useful generic behavior plus deeper root Node/npm and TypeScript analysis when repository evidence supports it.                                                                                                                            | Detection must change behavior, not only add a label. Python, Java, Go, workspaces, and deep pnpm/Yarn/Bun adapters remain outside the MVP.                                                                                                             |
| Shared inspection                    | Build one bounded, symlink-safe repository inventory and read selected text through shared containment and size limits.                                                                                                                            | Retain relative paths and file kinds rather than repository contents. Incomplete inventory cannot support definitive absence claims; static script heuristics never claim shell parsing or target-tool execution.                                       |
| Configuration and prerequisites      | Use one recursively strict Zod schema with optional JSON, adjacent `.env`, and process-environment overrides. Continue every independently runnable check when optional runtime configuration or credentials are absent.                           | Process environment overrides `.env`, then JSON, then defaults. Unknown, invalid, incomplete, or conflicting supplied values are fatal; missing optional services or credentials produce substantive skips. Target-specific values are never hardcoded. |
| Setup and scheduling                 | Validate the target, build shared state, and cache configured API/UI reachability before running four fixed analysis levels concurrently; run checks sequentially within each level.                                                               | Every check has a timeout and isolation boundary. Result order follows level and registration order, never completion timing.                                                                                                                           |
| Service and request safety           | Probe only configured API/UI targets, count any HTTP response as reachable, never scan ports, and never start, stop, or restart target services. Runtime API operations are limited to configured read-only `GET`, `HEAD`, and `OPTIONS` requests. | Dormant projects remain valid. Missing services produce fallback or skipped results; redirects, guessed hosts, unsafe methods, and lifecycle management are excluded.                                                                                   |
| Results, degradation, and exit codes | Runtime-validate every result and distinguish normal prerequisites or indeterminate evidence from incomplete execution/coverage. Return nonzero only for fatal tool errors.                                                                        | Status, finding, severity, and recommendation are mandatory even for skipped results. Isolated failures become redacted diagnostic rows and may make the summary incomplete; findings and unavailable services do not become CI policy.                 |

## Analysis Boundaries

| Decision                             | Agreed direction                                                                                                                                                                                            | Practical consequence                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repository quality                   | Use bounded evidence for `.gitignore`, lint/format configuration, tests, CI, TypeScript strictness, dependency freshness, lockfiles, and README quality.                                                    | Lint/format/test checks inspect readable nonempty artifacts and conservative npm-script evidence; Sentinel does not execute target quality scripts. Root npm freshness uses one bounded, script-disabled `npm outdated` query and skips cleanly when npm or the registry is unavailable.                                                                          |
| Dependency audit                     | Run a bounded audit only for a root npm project whose only recognized root lockfile is `package-lock.json`.                                                                                                 | A pass requires exit code 0 and a valid, internally consistent empty npm audit v2 report. Valid vulnerability output requires exit code 1; error envelopes, malformed output, and unexpected states never become a clean result.                                                                                                                                  |
| Secret and environment hygiene       | Detect only complete plausible private-key blocks, known provider credentials, and secret-like environment-file assignments; evaluate real `.env` files and templates separately through root ignore rules. | Findings retain relative path, line, and detector category only. Detector definitions, incomplete fragments, entropy scanning, generic source token heuristics, and Git-history scanning are excluded. Unignored real environment files warn High; ignored templates warn Low.                                                                                    |
| Runtime Security and debug discovery | Observe configured unauthenticated targets and evidence-derived debug routes with bounded read-only requests.                                                                                               | Cached reachability gates requests; target credentials are never resolved, redirects are not followed, and paths are not brute-forced. Weak or unverifiable header/CORS policy warns instead of passing. Source-derived Node/TypeScript route discovery is limited to debug candidates and is not API contract or AI evidence fallback.                           |
| OpenAPI and API mode                 | Require one explicit target-contained OpenAPI 3.0/3.1 JSON/YAML document and select live analysis or static fallback exclusively from cached API reachability.                                              | Sentinel never guesses or fetches a contract. Reachable APIs receive one request per bounded configured endpoint; unavailable APIs receive only static configured-endpoint alignment. Endpoint failures never switch mode. Validation remains shallow and source-route API fallback is not implemented.                                                           |
| Browser and forms                    | Use one composite Playwright Chromium check with shared public/authenticated contexts and only explicitly configured form flows.                                                                            | Page loads feed navigation, console, image, axe, and horizontal-overflow observations. Absence of overflow does not claim responsive adaptation. Indeterminate axe evidence blocks an accessibility pass without making successful execution incomplete. Forms run at the widest viewport, are bounded to approved steps, and are never discovered automatically. |

## AI and Secret Boundaries

| Decision                         | Agreed direction                                                                                                                                                                                                                                    | Practical consequence                                                                                                                                                                                                                            |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| AI use case and evidence         | Perform one semantic API test-gap analysis over one configured target OpenAPI contract and one related readable test selected through bounded, redacted repository evidence.                                                                        | Inspect at most 12 candidates, send at most 8 KiB, use target-relative citations, and skip without a request when safe relevant evidence is insufficient. Route-source fallback, multiple-test synthesis, and report summarization are excluded. |
| Provider and request model       | Require explicit OpenAI-or-Claude selection behind one provider-neutral typed client; use each vendor's native structured-output mechanism and validate locally with the same strict schema.                                                        | One client permits one paid request total and one active request. There is no provider inference, registry, retry, streaming, batching, free-text recovery, or provider comparison.                                                              |
| AI outcomes and failure handling | A validated supported gap may warn or fail; validated `no_supported_gap` is informational skipped; AI never passes. Disabled AI or a missing credential is a normal skip, while every unavailable or unrecognized dispatched response fails closed. | Dispatched failures consume the allowance, affect only the AI check, and mark execution incomplete. Missing safe evidence or credentials makes no paid request and leaves the scan complete.                                                     |
| Credential and evidence safety   | Redact repository and target secrets before storage, logging, reporting, or AI transmission. Use the selected provider credential only as an authentication header to that provider.                                                                | Real provider credentials never enter prompts, request bodies, response evidence, reports, logs, tests, documentation, or image layers. Target credentials are resolved only for explicitly protected targets and are never rendered.            |

## Delivery and Scope Control

| Decision                 | Agreed direction                                                                                                                                                              | Practical consequence                                                                                                                                                                                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tooling and verification | Use Commander, Zod, strict ESM TypeScript, Vitest, ESLint flat config, Prettier, Playwright, and axe. Keep `npm run check` as the shared local and CI gate.                   | Node.js 20.19 or later is required. Automated browser/provider/registry tests use deterministic fakes; the separately started sample supplies manual runtime validation.                                                                                                                     |
| Clean-machine setup      | Keep `npm install` followed by `npm start` as the authoritative zero-configuration path. Root installation also installs the standalone sample package with scripts disabled. | `prestart` compiles automatically. Native browser checks require a separate compatible Chromium installation; npm installation itself does not download a browser.                                                                                                                           |
| Optional Docker delivery | Build isolated Sentinel and sample images from one multi-stage Dockerfile and limit Compose to trusted-sample orchestration.                                                  | The scanner image installs Chromium and retains locked root dependencies; the deliberately vulnerable sample dependency remains in the production-only sample image. Direct scans use read-only mounts. Docker adds no image publication, Docker CI, or Sentinel service-lifecycle behavior. |
| Demo target              | Keep the deliberately flawed Express/TypeScript sample as a standalone nested npm project with its own manifest and lockfile.                                                 | Root-focused scans inspect a real package boundary. The reviewer or Compose starts the sample separately; Sentinel never manages it.                                                                                                                                                         |
| Scope control            | Prefer plain functions, fixed registration, and small explicit boundaries; complete requested work before stretch work.                                                       | Do not introduce plugins, DI containers, class hierarchies, schedulers, databases, additional providers/browsers/report formats, or deep stack adapters without approval.                                                                                                                    |

## Fatal Tool Errors

Fatal cases remain deliberately narrow:

- The target root cannot be read.
- Configuration cannot be interpreted safely or contains an unknown, invalid,
  conflicting, or incomplete supplied value.
- The selected report cannot be rendered or written.

All other unavailable capabilities and isolated check failures are represented
transparently in the report.
